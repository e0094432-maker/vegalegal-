# Bitrix24 → Telegram: клиенты по стадии + общие заметки

Бот показывает список сделок Bitrix24 на заданной стадии. Любой сотрудник
открывает бота, выбирает клиента и видит все заметки, оставленные коллегами
по этому клиенту (в т.ч. написанные другими людьми), и может добавить свою —
её увидят все.

## Как это работает

1. `/start` → кнопка «Показать клиентов на стадии».
2. Бот запрашивает у Bitrix24 (`crm.deal.list`) сделки с нужным `STAGE_ID`.
3. Список кликабелен — выбираете клиента.
4. Открывается карточка: название/сумма сделки, контакт, все заметки.
5. Кнопка «Добавить заметку» → пишете текст следующим сообщением → он
   сохраняется и виден всем, кто откроет карточку этого клиента.

Заметки хранятся локально в файле `notes.db` (SQLite), рядом с ботом —
это общая база для всех пользователей бота.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:

- **TELEGRAM_BOT_TOKEN** — создайте бота у [@BotFather](https://t.me/BotFather),
  скопируйте токен.
- **BITRIX_WEBHOOK_URL** — в Bitrix24: *Настройки → Разработчикам →
  Другое → Входящий вебхук*. Дайте права минимум на «CRM» (crm).
  Скопируйте URL вида `https://ваш-портал.bitrix24.ru/rest/1/xxxxxxxx/`
  (методом `.json` в конце дописывать не нужно — это делает код).
- **DEAL_STAGE_ID** — код нужной стадии сделки (см. ниже, как узнать).
- **DEAL_CATEGORY_ID** — если у вас несколько воронок и стадия не в
  основной, укажите ID воронки (можно оставить пустым для основной).

## Как узнать DEAL_STAGE_ID

Проще всего — открыть карточку сделки на нужной стадии в браузере и
посмотреть код колонки в настройках воронки (*CRM → Сделки → шестерёнка
→ Настроить стадии*), либо выполнить разовый запрос к Bitrix24:

```
https://ваш-портал.bitrix24.ru/rest/1/xxxxxxxx/crm.dealcategory.stage.list.json
```

В ответе будет список всех стадий всех воронок с полями `STATUS_ID`
(это и есть искомый `STAGE_ID`) и `NAME`.

В коде это же можно получить функцией `bitrix.list_deal_stages()` из
`bitrix.py` — при желании можно временно добавить отладочную команду в
`bot.py`, которая выведет список стадий прямо в Telegram.

## Запуск

```bash
python bot.py
```

Бот работает через long polling — отдельный сервер/домен не нужен,
достаточно, чтобы процесс был запущен (можно на VPS через `systemd`,
`pm2`, `screen`/`tmux` или Docker).

## Деплой: GitHub → Render

**Важно: `.env` не должен попасть в репозиторий** — там лежат живые токены.
Файл `.gitignore` уже это блокирует. Секреты вписываются в переменные
окружения на самой Render.

### 1. Залить в GitHub

```bash
cd bitrix_tg_bot
git init
git add .
git commit -m "Bitrix24 -> Telegram bot"
git branch -M main
git remote add origin https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПО.git
git push -u origin main
```

Проверьте `git status` перед коммитом — файла `.env` там быть не должно.

### 2. Создать сервис на Render

Бот работает через long polling (без HTTP-порта), поэтому это должен
быть **Background Worker**, а не Web Service.

В репозитории уже лежит `render.yaml` — при создании через
*New → Blueprint* на Render он подхватится автоматически и настроит:
- тип сервиса — Background Worker,
- команду сборки/запуска,
- Persistent Disk на 1 ГБ, смонтированный в `/var/data` (там будет
  жить `notes.db`, чтобы заметки не терялись при redeploy).

Либо вручную: *New → Background Worker* → подключить репозиторий →

| Поле | Значение |
|---|---|
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python bot.py` |

Затем во вкладке **Environment** добавьте переменные:

| Ключ | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | ваш токен от BotFather |
| `BITRIX_WEBHOOK_URL` | ваш вебхук Bitrix24 |
| `DEAL_STAGE_ID` | `PREPARATION` |
| `DEAL_CATEGORY_ID` | (оставить пустым) |
| `DB_PATH` | `/var/data/notes.db` (если добавили Persistent Disk) |

Если делаете вручную, не забудьте добавить и сам диск: *Disks → Add Disk*
→ путь `/var/data`, размер 1 ГБ.

### 3. Проверка

После деплоя во вкладке **Logs** должна появиться строка «Бот запущен».
Пишете боту `/start` в Telegram — должен ответить.

## Возможные доработки (скажите, если нужно)

- Дублировать заметки в таймлайн сделки в самом Bitrix24
  (`crm.timeline.comment.add`), чтобы они были видны и там.
- Ограничить список только сделками, назначенными на конкретного
  сотрудника (`ASSIGNED_BY_ID`).
- Уведомлять всех сотрудников в общем чате при добавлении новой заметки.
- Показывать telegram-username автора заметки, а не только имя.
- Автообновление списка клиентов по расписанию/вебхуку из Bitrix24
  вместо запроса по кнопке.
